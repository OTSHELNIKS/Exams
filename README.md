# NAME — соревновательный матчмейкинг MLBB

**Сайт (рабочий, с бэкендом Supabase):**
https://name-mlbb.netlify.app
— деплой на Netlify напрямую из GitHub: каждый пуш в ветку
`arena/cc650609-exams` сам пересобирает и публикует сайт
(настройки в [`netlify.toml`](./netlify.toml)). После регистрации по почте
подтвердите email по письму и вернитесь по ссылке, чтобы войти.

Реализация проекта по презентации заказчика:
[папка с видео на Google Диске](https://drive.google.com/drive/folders/1NkWbVfC0ya0yPKKve7BPyAK1mQ0dG8x1)
(`VID_20261027_190901_779.mp4`, 7 минут).

Видео — это **показной макет** (по словам заказчика, ~50–60 % итогового продукта):
соревновательный матчмейкинг для **Mobile Legends: Bang Bang**, а также промо-сайт для приложения.
Я посмотрел видео (кадры + расшифровка речи), вынес требования в
[`docs/ТЗ-заказчика.md`](./docs/ТЗ-заказчика.md) и собрал работающее приложение.

## Что сделано

### 1. Промо-сайт
- Hero «Играй. Побеждай. Зарабатывай.», живой телефон с экраном входа.
- Блок возможностей (честный драфт, выбор сервера, боты-лобби, войс, античит, призы).
- Путь игрока из 4 шагов, экономика призов, блок для рекламодателей/партнёров.
- CTA «Открыть приложение» переключает в приложение.

### 2. Мобильное приложение — 7 экранов макета

| # | Экран | Что работает |
|---|-------|--------------|
| 1 | Вход | Привязка Game ID, вход по почте, ссылка на Telegram-бота, плашка античита |
| 2 | Заполните профиль | 3 шага: фото+ник+возраст+пол+ранг; мультироли; **выбор серверов/регионов**; «О себе»; любимые герои; загрузка скриншота с проверкой ботом |
| 3 | Главная | Чистый старт: Game ID, аватар, ELO/роль (появляются после заполнения анкеты), пустые состояния с подсказками, доп. слоты, привязка соцсетей, партнёрский баннер |
| 4 | Профиль игрока | Профиль в развёрнутом виде + кнопка настроек (редактирование анкеты) |
| 5 | Captain's Draft | Два капитана, монетка (кто первый), таймер хода, фильтры по ролям, пул из 8 игроков с винрейтом/KDA/ролью, карточка игрока, поочерёдный выбор и заполнение слотов команд |
| 6 | Матч готов | ID лобби с копированием, голосовой чат 5/5 с мутами и индикаторами речи, микрофон/выход, блок авто-парсинга скриншота |
| 7 | Таблица лидеров | Вкладки Сезон / Месяц / Друзья, обычная и про-лига, призы топ-3, ELO, короны про-игроков |

Без входа профиль хранится в `localStorage`, после входа по почте — в Supabase.
Старт всегда чистый: все данные вводит сам пользователь через анкету, кнопка
«Очистить анкету» внизу анкеты сбрасывает всё. На десктопе есть боковая панель
быстрого перехода по всем экранам, на мобильном — нижняя навигация. Приложение
адаптивно: на телефоне занимает весь экран и использует системный статус-бар
устройства, на десктопе показывается нейтральной колонкой без фальшивой «шторки».
Данные других игроков (драфт-пул, матч, рейтинг) — пока заглушки,
серверная часть для них в roadmap.

## Запуск

```bash
cd app
npm install
npm run dev
```

Откройте `http://localhost:5173/` (в Arena — live preview на порту 5173).
Сборка: `npm run build`, предпросмотр сборки: `npm run preview`.

Стек: React 18 + Vite 6, CSS без фреймворков, иконки `lucide-react`,
шрифты `Unbounded` и `Inter` (устанавливаются из npm, без внешних CDN).

## Деплой

Сайт собирается из GitHub на Netlify автоматически при пуше в
`arena/cc650609-exams` (конфиг — [`netlify.toml`](./netlify.toml)).
Обязательные условия: в Site settings → Environment variables заданы
`VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`, ветка деплоя —
`arena/cc650609-exams`. Значения `VITE_*` специально вшиваются в клиентский
JS (publishable-ключ публичен по дизайну), поэтому они исключены из
Netlify secrets scanning через `SECRETS_SCAN_OMIT_KEYS`.

Ручной вариант: `cd app && npm run build`, залить папку `dist` через
Netlify Drop. Однофайловый `npm run build:singlefile` оставлен только для
превью в чате.

## Что реально, а что пока сценарий

Реально работают на Supabase: вход по почте, анкеты, фото и скриншоты,
админка, Telegram-бот (привязка, команды, ID лобби). Пока остаются
UI-сценариями с заглушками: realtime драфта и матча, голосовой чат,
платежи и проверка скриншотов (см. roadmap).

## Подключение Supabase: аккаунт, профиль и медиа

В репозитории подготовлена интеграция входа по email/паролю, сохранения анкеты
и загрузки фото и скриншотов. Она включается переменными окружения (см. ниже);
без них приложение работает на `localStorage` без сервера.

1. Создайте проект в Supabase и примените **все** SQL из `supabase/migrations/`
   через SQL Editor или Supabase CLI, по порядку:
   - `20261028000000_profiles.sql` — таблица `player_profiles` с RLS:
     пользователь читает и изменяет только свою анкету;
   - `20261028230000_profile_media_storage.sql` — бакеты `avatars` и `screenshots`
     (публичное чтение, запись только в свою папку) + колонки `avatar_url`,
     `screenshot_urls`.
   - `20261028234500_admins_and_persistent_socials.sql` — колонки `socials`,
     `extra_slots`, таблица `admins` и чтение всех анкет для админов.
   - `20261028235500_telegram_linking.sql` — таблицы `telegram_links`,
     `telegram_link_codes` и серверная колонка `pts` (клиентам запрещена запись).
2. Включите Email provider в Auth. Если включено подтверждение почты, добавьте URL
   приложения в настройки redirect URL и настройте доставку писем.
3. Скопируйте `app/.env.example` в `app/.env` и укажите URL проекта и
   **публичный publishable/anon key**. Секретный ключ или `service_role`
   в браузере использовать нельзя. Перезапустите Vite.
4. Войдите по почте на экране входа, заполните анкету, загрузите фото
   (JPG/PNG/WebP/GIF до 5 МБ) и до 4 скриншотов статистики, сохраните.
   Для нового аккаунта может потребоваться подтвердить email.

Без входа загрузки фото и скриншотов работают как локальный предпросмотр
и не покидают браузер. Привязки соцсетей и доп. слоты сохраняются в базе
(настоящей оплаты пока нет). Рейтинг, верификация, драфт, матчи
и голосовой чат — пока UI-сценарии, для них нужны серверная логика
и интеграции (см. roadmap).

## Админка

Экран «Админка» (кнопка ADMIN на главной, пункт в навигации) виден только
администраторам. Админ видит всех пользователей: статистику, поиск по нику
и Game ID, полные анкеты с фото и скриншотами. Обычные пользователи видят
только свой собственный профиль.

Назначить админа может только владелец базы — клиентским кодом это сделать
нельзя (политик на запись в `admins` нет). Зарегистрируйтесь в приложении,
затем выполните в SQL Editor Supabase:

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'YOU@example.com'
on conflict do nothing;
```

После этого перезайдите в приложение — появится доступ в админку.

## Telegram-бот

Бот `@name_mlbb_bot` — webhook на Edge Function `telegram-bot` (код в
[`supabase/functions/telegram-bot/`](./supabase/functions/telegram-bot/)).
Умеет: привязку аккаунта по 6-значному коду из профиля, команды `/profile`,
`/rating`, `/unlink`, `/help` и отправку ID лобби в личку из экрана матча.

Привязка: Профиль → «Привязать Telegram» → код → кнопка «Открыть бота»
(или вручную `t.me/name_mlbb_bot?start=КОД`). Приложение само заметит
привязку. Отвязка — там же или командой `/unlink` в боте.

Безопасность: токен бота и секреты живут только в server-side secrets
Supabase (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`,
`TELEGRAM_SETUP_SECRET`, `APP_PUBLIC_URL`) — в репозитории и фронте их нет.
Telegram-запросы проверяются по секретному заголовку webhook, вызовы
уведомлений из приложения — по JWT пользователя и только себе.
Колонка `pts` закрыта от записи клиентским кодом (REVOKE).

Ссылка на сайт в сообщениях бота (`APP_PUBLIC_URL`):
https://name-mlbb.netlify.app

Развёртывание с нуля: примените миграции, задеплойте функцию с
`verify_jwt=false`, задайте 4 секрета и один раз откройте в браузере
`https://YOUR_REF.supabase.co/functions/v1/telegram-bot?setup=SETUP_SECRET`
— это пропишет webhook и команды бота.
