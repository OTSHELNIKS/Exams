# Задание 2 — база данных и загрузка исходных данных

## Запуск

Из корня репозитория:

```bash
python3 solutions/task2_database/seed.py
```

Создаётся `manufacturing.sqlite3`. Скрипт применяет `schema.sql`, импортирует `Заказчики.json`, а также остальные предоставленные JSON, чтобы сразу можно было проверить задание 3. Для другой папки с исходниками используйте `--data-dir`, для другого имени базы — `--db-path`.

## Таблицы

`customers`, `customer_orders`, `order_items`, `products`, `resources`, `product_specification`, `prices`, `discounts`, `production_orders`, `production_order_items`.

- Покупатели/поставщики отделены от заказов.
- Строка клиентского заказа хранит количество, снимок цены и скидку на единицу; эти значения не смешиваются с текущим прайс-листом.
- Ресурс имеет тип «Материал» или «Операция»; обе разновидности входят в спецификацию и участвуют в расчёте себестоимости.
- `prices`/`discounts` используют два nullable FK и CHECK-ограничение: запись относится ровно к одному товару либо ресурсу.
- Внешние ключи включены; `PRAGMA foreign_key_check` после импорта не находит нарушений.

## Обнаруженные несоответствия исходных JSON

Чтобы не терять строки и одновременно сохранить PK/FK:

- в справочнике товаров отсутствуют `product_id` **398, 881, 942**, хотя на них ссылаются позиции/спецификации/цены. Для них созданы явно помеченные записи-заглушки (`is_placeholder=1`);
- повторяется `product_id=887` (диван и овальный стол переговорный). Обе строки сохранены: первой оставлен ID 887, второй выдан внутренний surrogate key; источник цены со ссылкой только на 887 сопоставлен первой записи, поскольку разрешить неоднозначность по JSON нельзя;
- повторяется `resource_id=456` (материал и операция). Обе строки сохранены под разными внутренними ключами; цена/скидка уточняется по `item_type`;
- `id` позиций заказа повторяется (31 и 81), а `id` скидок — 15. Строки сохранены, внутренние PK сгенерированы отдельно, исходные ID записаны в `source_order_item_id` и `source_discount_id`.

Это не меняет заказ № 1, используемый в контрольном расчёте, но важно для целостной загрузки всего набора.
