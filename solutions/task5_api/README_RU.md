# Задание 5 — API и коллекция тестов

API размещён в `../task4_auth_api/app.py`, чтобы авторизация, таблица `users` и заметки использовали одну БД.

## Эндпоинты

- `GET /notes` — основной маршрут.
- `GET /api/notes` — алиас.
- Необязательные query-параметры: `limit` (целое число 1–1000), `user_id` (положительное целое число). Неизвестный, повторный или некорректный параметр возвращает `400` с JSON-полем `error`.
- В штатном режиме ответ — JSON-массив. Если записей нет, корректный ответ — `200 OK` и `[]`.
- В объекте заметки `title_user` собирается как `title + " - " + login`, `content` передаётся без изменений, `created_at` преобразуется в `ДД.ММ.ГГГГ`.
- Ошибка базы данных возвращает `500` с JSON. Для неподдерживаемого HTTP-метода — `405` и `Allow: GET`.

## Проверка

Основные автоматические тесты (код ответа, JSON, формат полей/даты, пустой результат, 400, 500, 405 и блокировка входа после трёх ошибок):

```bash
python3 -m unittest discover -s solutions/task4_auth_api/tests -v
```

Коллекция и окружение Postman:

- `Exam_API.postman_collection.json`
- `Exam_API.postman_environment.json`

Импортируйте оба файла в Postman, запустите обычный сервер на порту 8000 и выполните коллекцию. Для проверки сценария 500 поднимите отдельный тестовый экземпляр на 8001:

```bash
EXAM_TEST_MODE=1 EXAM_FORCE_DB_ERROR=1 APP_PORT=8001 \
EXAM_DB_PATH=/tmp/exam_api_fault.sqlite3 \
python3 solutions/task4_auth_api/app.py
```

В тестовом экземпляре принудительная ошибка включается только при обоих флагах `EXAM_TEST_MODE=1` и `EXAM_FORCE_DB_ERROR=1`; в обычном запуске API этот режим выключен. На Windows PowerShell задайте эти переменные через `$env:...` перед запуском.
