# NAME MLBB — чек-лист и тест-кейсы

Сайт: https://name-mlbb.netlify.app · Бот: @name_mlbb_bot (функция v9) · База: Supabase `yjedqdbwvjvikyixsduw`

## Как запускать автотесты

```bash
node tests/bot.test.mjs   # 21 тест логики бота, ноль зависимостей
```

Тест грузит **настоящий** `supabase/functions/telegram-bot/index.ts`, подменяет `Deno`/`fetch`
и гоняет фейковые апдейты Telegram + вызовы `?action=notify` / `?setup` / `?health`.

Проверки базы (RLS) — через SQL с impersonation роли, см. `T-DB-*` ниже:

```sql
reset role; set role authenticated;
set request.jwt.claims to '{"sub":"<user-uuid>"}';
-- ... проверяемый запрос ...
```

Проверки фронта: `npm run build` в `app/`, grep на отсутствие захардкоженных
пользователей, раздача `dist` + контроль маркеров в бандле.

## Известные ограничения

- FK `moderation_reviews.user_id` сохранил старое имя `screenshot_reviews_user_id_fkey`
  (косметика после переименования таблицы, на работу не влияет).
- Кросс-юзерный RLS-тест на чтение покрыт (T-DB-04); на запись — через несуществующий
  UUID (T-DB-07, RLS срабатывает раньше FK). Полный двухпользовательский e2e —
  только руками (M-кейсы), когда появится второй реальный аккаунт.
