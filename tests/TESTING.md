# NAME MLBB — чек-лист и тест-кейсы

Сайт: https://otshelniks.github.io/Exams/ (GitHub Pages) · зеркало: https://name-mlbb.netlify.app · Бот: @name_mlbb_bot (функция v17, сборка `greeting-v2`) · База: Supabase `yjedqdbwvjvikyixsduw`

## Как запускать автотесты

```bash
node tests/bot.test.mjs     # 48 тестов логики бота, ноль зависимостей
node tests/admin.test.mjs   # 11 проверок админки и оверлея карточки (статические)
node tests/avatar.test.mjs  # 7 проверок геометрии обрезки аватарки
node tests/heroes.test.mjs  # 9 проверок каталога героев и иконок
node tests/gameid.test.mjs  # 10 проверок раздельного хранения Game ID и сервера
node tests/typography.test.mjs  # 5 проверок читаемости шрифтов на десктопе
node tests/auth-methods.test.mjs  # 8 проверок способов регистрации
node tests/auth-return.test.mjs  # 7 проверок возврата с внешнего входа
node tests/socials.test.mjs  # 10 проверок привязки соцсетей
```

Тест грузит **настоящий** `supabase/functions/telegram-bot/index.ts`, подменяет `Deno`/`fetch`
и гоняет фейковые апдейты Telegram + вызовы `?action=notify` / `?setup` / `?health`.

Проверки базы (RLS) — через SQL с impersonation роли, см. `T-DB-*` ниже:

```sql
reset role; set role authenticated;
set request.jwt.claims to '{"sub":"<user-uuid>"}';
-- ... проверяемый запрос ...
```

Проверки фронта: `npm run build` в `app/`, grep на отсутствие захардкоженных
пользователей, раздача `dist` + контроль маркеров в бандле.

## Известные ограничения

- FK `moderation_reviews.user_id` сохранил старое имя `screenshot_reviews_user_id_fkey`
  (косметика после переименования таблицы, на работу не влияет).
- Кросс-юзерный RLS-тест на чтение покрыт (T-DB-04); на запись — через несуществующий
  UUID (T-DB-07, RLS срабатывает раньше FK). Полный двухпользовательский e2e —
  только руками (M-кейсы), когда появится второй реальный аккаунт.
